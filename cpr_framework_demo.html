Welcome to the CPR Framework

What is this? This interactive demonstration showcases a groundbreaking discovery in the study of constrained dynamical systems: a universal law governing when simple rules produce complex emergent behavior.

Key Discovery

Through 312 systematic experiments, we identified that the Constraint Pressure Ratio (CPR) predicts the emergence of complexity in discrete dynamical systems. But there's more: constraints fall into two distinct universality classes, each requiring different prediction models.

The Core Equation

CPR = n / (b^n)

Where: n = system size (number of components) b = base (number of states per component)

CPR measures the "search problem" a constrained system faces: how many constraints (proportional to n) must navigate how large a state space (exponentially proportional to b^n).

Theoretical Foundation

1. The Central Thesis: Scale-Dependent Emergence

The foundational discovery is that the relationship between rules (constraints) and behavioral complexity is not fixed but is scale-dependent. The same set of constraints that produces simple, ordered behavior in small-scale systems can actively guide a large-scale system into a state of high complexity and novelty.

Key Insight: Emergent behavior is not a property of the system's components or its rules in isolation, but of the interaction between the rules and the vastness of the system's state space.

2. The Constraint Pressure Ratio (CPR)

The CPR is a universal metric that robustly predicts the behavioral regime of a system:

CPR = n / (b^n) Interpretation: Numerator (n): Scale of constraints (linear growth) Denominator (b^n): Scale of state space (exponential growth) → CPR quantifies the "search difficulty"

Experimental data from 312 distinct architectural configurations confirms that CPR, not size or base alone, is the primary predictor of system behavior.

Important: Raw CPR vs Adjusted CPR

The raw CPR measures the theoretical constraint pressure based only on system size and base. However, different architectural choices (constraint type, mixing function, governor strategy) affect the effective state space available for exploration.

Adjusted CPR = Raw CPR × Architecture Adjustment Factor

The sigmoid model uses Adjusted CPR to make predictions, accounting for how architecture reduces the valid state space.

2b. How the System Works and What Is Measured

Every data point comes from a discrete dynamical simulation. The system holds n components, each taking one of b integer values. Starting from a random state, each step applies three operators in sequence, and the system runs for thousands of steps while recording every state it visits:

OperatorRole
MixCombines neighboring components to propose the next state (additive, multiplicative, or triple_sum)
Corrector (Constraint)Rejects or repairs states that violate the active constraint — this enforces the constraint type
GovernorSteers long-run statistics toward a target (uniform_distribution or entropy_maximization)

The two measured outputs are defined operationally as:

Exploration (E) = (number of DISTINCT states visited) / (number of steps) → the "unique-state fraction" of the run, range [0, 1] → E = 1.0 means every step produced a brand-new state Complexity (C) = Shannon-entropy-based BEHAVIORAL complexity of the visited-state sequence, range [0, 2.4467] → how rich/disordered the realized trajectory is → distinct from combinatorial (state-count) complexity

The Four Constraint Mechanisms

The raw experiments record four concrete Corrector rules, which group into the two universality classes:

  • adjacent_duplicates (structure-based): forbids states where two adjacent components are equal — a "repulsion" preventing neighboring repeats.
  • pattern_prohibition (structure-based): forbids specific sequential patterns in the component string.
  • sum_limits / sum_modulation (density-based): forbids states whose component sum lands on disallowed values.
  • local_entropy (density-based): rejects states with too little local disorder.

Where CPR = n / bⁿ Comes From

CPR is not arbitrary. For the adjacent-duplicate Corrector, the original analysis measured that the per-step probability the constraint must act ≈ n / b (the "Corrector Constraint Ratio"): collisions get more likely with more positions n and less likely with more per-position freedom b.

CPR lifts this local ratio to a global scale, comparing the linear growth of constraint pressure (∝ n) against the exponential size of the whole state space (bⁿ). When CPR is tiny, the state space dwarfs the constraints and the system has room to explore (emergent); when CPR is larger, constraints occupy a meaningful fraction of a small space (constrained). The n/b ratio is the microscopic seed; n/bⁿ is the global metric that predicts the regime across 35 orders of magnitude.

3. The Phase Transition

For density-based constraints (Class I), the transition from constrained to emergent behavior is modeled by a sigmoid function:

E = L / (1 + e^(k × (log₁₀(Adjusted_CPR) - x₀))) Parameters (fitted to 70 data points in critical transition zone): L = 0.8513 (maximum exploration ceiling) k = 46.7978 (steepness - extremely sharp!) x₀ = -8.2999 (critical point) Critical Adjusted_CPR: 10^(-8.3) ≈ 5.01 × 10^(-9) Direction: E → L as CPR falls below the critical point (emergent), E → 0 as CPR rises above it (constrained)

The extremely high steepness (k ≈ 47) indicates a "snap-like" transition, suggesting high cooperativity among system components and potential hysteresis effects.

Sign-Convention Correction

Earlier project documents wrote this formula with e^(−k × …) and a positive k. That form rises with CPR — the opposite of every measurement in the dataset (mean measured exploration is 0.64 where log₁₀(CPR) < −15 versus 0.09 where log₁₀(CPR) > −7). The form shown above, equivalent to quoting k as negative in the old form, is the orientation that matches the data, the regime definitions, and the description of L as the emergent-regime ceiling.

Model Scope and Interpretation

The sigmoid model predicts the CENTRAL TREND, not individual outcomes. The model was fitted to 70 carefully selected data points spanning the critical transition region. While the overall trend is highly accurate (R² > 0.95 for the central tendency), individual architectural configurations show natural scatter around this trend due to specific implementation details.

Key Point: The sigmoid tells you what regime you're in and the typical exploration level for that regime. Individual architectures may perform above or below this trend, which is why architecture-specific adjustment factors are crucial.

4. Regimes of Behavior

Important: Regime boundaries are defined using Adjusted CPR, not raw CPR.

Regime log₁₀(Adjusted CPR) Characteristics Behavior
Constrained > -7.8 Small effective state space, high pressure Low complexity, minimal exploration
Critical -8.8 to -7.8 Balanced constraint-space ratio Rapid transition, architectural sensitivity
Emergent < -8.8 Vast effective state space, low pressure High complexity, extensive exploration

Understanding Regime Classification

A system with raw CPR = 1×10⁻⁷ (log₁₀ = -7.0) might appear to be near the critical regime. However, with an adjustment factor of 5.0×, the adjusted CPR becomes 5×10⁻⁷ (log₁₀ = -6.3), placing it firmly in the constrained regime. Always use adjusted CPR for regime determination.

5. Architecture Adjustment Factors

The specific architecture (constraint type, mixing function, governor strategy) modifies the effective CPR through adjustment factors ranging from 1.5× to 7.34×:

Adjusted_CPR = CPR × Architecture_Adjustment_Factor Where the factor accounts for: - Constraint type (primary influence) - Mixing type (secondary influence) - Governor type (tertiary influence) Example: Raw CPR = 1.0×10⁻⁶ (from system size and base) Adjustment Factor = 3.8× (pattern_prohibition + additive + uniform) Adjusted CPR = 3.8×10⁻⁶ (used in sigmoid prediction)

Why Adjustment Factors > 1.0

Adjustment factors greater than 1.0 indicate that the architecture reduces the valid state space. A factor of 3.8× means the effective constraint pressure is 3.8 times higher than the raw CPR would suggest, shifting the system toward more constrained behavior.

6. The Two-Model Discovery

Critical Finding: Not All Constraints Follow CPR-Sigmoid

30% of architectures (all using pattern_prohibition) failed to align with the sigmoid model. Investigation revealed they follow a fundamentally different relationship:

For pattern_prohibition (Class II - Structure-Based):

E = C / C_max Where: C = Realized behavioral complexity (measured from the run) C_max = 2.4467 (maximum complexity OBSERVED in the 312 experiments, an empirical calibration constant — not a theoretical bound) This is a LINEAR relationship, not sigmoid!

Why the difference?

  • Density-based constraints (sum_modulation, local_entropy): Uniformly reduce the valid state space. CPR directly predicts exploration.
  • Structure-based constraints (pattern_prohibition): Create sequential dependencies. CPR determines valid states, but pattern structure determines which are reachable. Complexity captures reachability.

7. Hybrid Model System

The complete prediction framework uses model selection based on constraint type:

IF constraint == 'pattern_prohibition': E = C / C_max (Complexity model) ELSE: E = Sigmoid(log₁₀(Adjusted_CPR)) (CPR model) Result: 100% architecture coverage RMSE < 0.03 for all architectures R² > 0.98 for all architectures

8. Theoretical Implications

This framework reveals that constrained dynamical systems fall into distinct universality classes:

  • Class I (Density-Based): Sigmoid phase transition, universal CPR scaling
  • Class II (Structure-Based): Linear complexity scaling, architecture-dependent mapping

This classification may extend to:

  • Statistical mechanics (different constraint types in partition functions)
  • Information theory (channel capacity under different constraint forms)
  • Optimization theory (constraint geometry effects on search landscapes)

Understanding the Two Constraint Classes

The Discovery That Changed Everything

Initially, we believed CPR could predict all constrained systems via a universal sigmoid. But 30% of architectures failed this model. The breakthrough came when we recognized that constraints fall into two fundamentally different classes.

Class I: Density-Based Constraints Density

Examples: sum_modulation, local_entropy

Mechanism: These constraints reduce the density of valid states uniformly across the state space. For example, sum_modulation might forbid states where the sum of components equals certain values.

Effect: Total states = b^n Valid states = b^n × (1 - reduction_fraction) CPR directly predicts exploration Model: E = Sigmoid(log₁₀(CPR))

Characteristics:

  • Universal sigmoid phase transition
  • Sharp critical point at CPR ≈ 5×10⁻⁹
  • Steepness k ≈ 47 (extremely abrupt transition)
  • Predictable from CPR alone (with architecture adjustments)

Class II: Structure-Based Constraints Structure

Example: pattern_prohibition

Mechanism: These constraints create sequential dependencies between states. Pattern prohibition forbids certain subsequence patterns, creating temporal structure.

Effect: CPR determines valid states Pattern structure determines REACHABLE states Complexity measures effective reachability Model: E = C / C_max (linear relationship!)

Characteristics:

  • Linear complexity-exploration relationship
  • No universal CPR scaling
  • Complex → Exploration ratio nearly constant (≈2.0-2.5)
  • Requires complexity measurement for accurate prediction

Why Pattern Prohibition is Different

Pattern prohibition creates a two-stage process:

  1. Stage 1: CPR determines the set of valid state sequences
  2. Stage 2: Pattern structure determines which valid sequences are actually reachable from any starting state

The sigmoid model tries to predict the final outcome (exploration) directly from CPR, skipping stage 2. This fails because stage 2 has complex, nonlinear dynamics that can't be captured by CPR alone.

The complexity-based model works because complexity directly measures the output of stage 2 (reachability). The relationship Complexity → Exploration is simple and linear.

Practical Implications

How to Use This Classification

For density-based constraints: Calculate CPR, apply architecture adjustment, use sigmoid model. No complexity measurement needed.

For structure-based constraints: Must measure (or estimate) complexity. Use E = C / C_max. CPR is less predictive.

Unknown constraint types: Test on small systems. If C/E ratio is constant across CPR values → structure-based. If it varies → density-based.

Honest caveats

1. Inputs differ by class. Structure-based predictions (Class II) take the experiment's measured complexity as input — that is the hybrid model's design (E = f(C)), but it means those points test the C→E relationship, not a from-scratch prediction. Density-based predictions (Class I) use only CPR and the architecture adjustment factor.

2. Live metrics differ from the historical tables. Recomputing from the embedded data reproduces the structure-based figures almost exactly (live R² ≈ 0.997 vs the documented 0.9974). The density-based figures (documented RMSE < 0.03, R² > 0.98) do not reproduce: the sigmoid predicts the central trend and regime, but at any given CPR the density-based experiments split into high-performing bands (e.g., additive + uniform_distribution, near E ≈ 1 in the emergent regime) and suppressed bands (e.g., multiplicative mixing, near E ≈ 0 regardless of CPR). The ×1.5–×7.34 adjustment factors shift log₁₀(CPR) by under one order of magnitude and cannot account for that spread. Treat the sigmoid as a regime classifier with a typical-performance curve, not a point predictor for every architecture.
